# Local trust, privacy and resource boundaries

MLForge targets one user on a trusted Windows/Linux computer. Both UI and API bind to `127.0.0.1`. FastAPI limits accepted hosts to localhost/loopback (plus its test client) and enables no cross-origin browser policy. It has no authentication/authorization layer; network exposure is outside this release. Do not publish either local port to an untrusted network.

The separately configured public demo starts only Streamlit inside a hosted container. It keeps a generated workspace for each Streamlit session under temporary server storage; the local REST server is not started there. CORS and XSRF protections remain enabled. Hosted data and artifacts can disappear on restart, scale-to-zero or reconnection. Public/synthetic inputs are appropriate for the demo; use the local option for private data and persistent history. There are no user accounts, durable tenant identities or guarantees that an interrupted browser session can recover its workspace. Each session has smaller input limits and bounded dataset/experiment/model counts. Hosting still shares finite server resources and is not an audited multi-tenant service.

CSV bytes, rows, columns and cells are bounded. UTF-8 decoding, headers, quoting, row widths, missingness and numeric finiteness/magnitude are validated before training. Uploaded names are display-only sanitized basenames. Actual file paths use generated UUIDs; no API client supplies a filesystem artifact path. Prediction schemas reject extra/missing fields, wrong numeric/string/boolean values, oversized batches and non-finite/excessive numbers. The ASGI wrapper counts body bytes before parsing, including requests without Content-Length, and refuses bodies over 1 MiB. Transport-level oversized-body rejections occur before service logging; normal validation failures are recorded without raw inputs.

SQLite parameterized queries store metadata. Transactional reservation permits one active experiment, and a file lock guards worker execution. Workers receive only a validated saved config and app-owned dataset ID, never user scripts. Deadlines and cancellation apply to matching app-owned process IDs plus creation timestamps/command identity. API errors return safe messages rather than tracebacks or absolute filesystem paths. Structured failure/worker logs carry event IDs, state and timings, not private prediction rows.

Joblib uses executable pickle serialization. Only application-created experiment artifacts can be registered; there is no artifact upload/import API. Loading derives a path from the local model ID, checks format and environment compatibility, and verifies SHA-256 before deserialization. This catches missing, incompatible or modified artifacts; it does **not** protect against someone controlling the local account, database and checksum. Do not put files from untrusted sources in runtime storage. Model status is an explicit registry state, not an automatic deployment or approval decision.

Canonical uploaded CSVs stay locally for profiling and reproduction until the user confirms deletion. Dataset deletion removes its CSV/listing, while experiment metadata and model training summaries remain. Registry artifact deletion leaves a metadata tombstone for version history, and retains the original experiment pipeline. These actions are not promises of complete forensic data erasure. Models, category vocabularies, profiles, target/prediction examples and aggregate statistics can reveal sensitive information; protect the entire runtime directory. Files/SQLite are not encrypted by the application.

Monitoring retains no raw input rows or per-row prediction arrays. It keeps only model/version, timestamp, row count, duration, status/error, aggregate prediction summaries and bounded per-feature drift summaries. Training reference categorical frequencies are local model metadata. Latest 1000 requests/30 days are enforced on startup, logging and monitoring reads; all logs can be explicitly cleared in the UI. Synthetic drift requests are labeled. Input shift is not a measurement of accuracy degradation; obtaining real outcome labels is required for that.

`.gitignore` excludes virtual environments, local runtime data, uploaded CSV storage, databases, trained joblib artifacts, logs, caches, `.env` and build output. No credentials are needed. Private resumes inspected during the environment audit are not copied into this repository.
